# v0.1.0-alpha.1 release candidate

Supabase User MCP `v0.1.0-alpha.1` packages the experimentally accepted local
principal-bound read path already present on `main`. It is an independent application data-plane
MCP for Supabase, distinct from Supabase's hosted developer control-plane MCP.

## Exercised capability

- local stdio transport with a verified Supabase user credential loaded from the environment;
- fixed read-only `memory_search`, `memory_get`, and `memory_list_recent` capabilities;
- verified principal context preserved through fixed Data API/RPC calls;
- PostgreSQL Row Level Security as the final row-authorization boundary;
- principal-scoped rate limiting and bounded request IDs, frames, rows, bytes, time, and concurrency;
- explicitly untrusted model-visible content and redacted operational attribution;
- synthetic cross-principal, revocation, denial, and M2 acceptance evidence;
- synthetic/local governed-artifact inspection contracts and bounded deterministic primitives through
  S5a, without a live Storage adapter or persistent receipt backend.

## Explicit exclusions

This alpha is not production-ready. It provides no remote HTTP or OAuth profile, governed write path,
live Storage adapter, hosted artifact inspection, semantic/vector search, deployment, private-data
acceptance, or caller-selected SQL/table/schema/RPC/URL surface. No `service_role`, database-admin,
privileged Storage, or other master credential belongs in the normal user request path.

Remote HTTP plus Supabase OAuth 2.1 is the separately gated next profile under
[issue #60](https://github.com/jryski/Supabase_user_MCP/issues/60) and
[issue #62](https://github.com/jryski/Supabase_user_MCP/issues/62). It is not part of this release
candidate and must resolve the intended-resource and downstream-token boundary before acceptance.

## Verification coordinate

The release candidate must be evaluated at its exact pull-request head. Passing Build, M2, Markdown,
and Links checks demonstrates reproducibility at that coordinate. It does not constitute merge,
publication, deployment, production readiness, or final security acceptance.

No tag, GitHub release, npm publication, or deployment is created by this candidate. Jesse retains the
publication decision after exact-head review.
